# Data Pipeline & Environment Setup

This project uses **Hugging Face Hub** for dataset access and **PyTorch** for model training. Follow the steps below to set up your environment and prepare the data.

---

## 1. Environment Configuration

To access the datasets with higher rate limits, you must use a Hugging Face token.

1. Locate the `.env.example` file in the root directory.
2. Open it and paste your Hugging Face User Access Token.
3. Rename the file to `.env`.

> **Important:** The `.env` file is included in `.gitignore` and should never be committed to the repository to keep your credentials secret.

---

## 2. Downloading the Dataset

The script `src/download_dataset.py` handles the data acquisition from the `mateuszgrzyb/lichess-stockfish-normalized` repository.

### Usage
We'll use two datasets:

* Run the script with `nrows = 100_000`. This creates a lightweight file to verify that the training loop and loss functions are working correctly.
* Run the script with `nrows = 5_000_000` for the final training. (This may take at least 30 minutes to download and process.)

The data is filtered for unique positions and saved locally in the **Apache Parquet** format (`.parquet`). This format offers high compression and fast I/O, significantly reducing disk usage (~96MB for 5M rows).

The script uses a fixed random seed to ensure that all developers have the same dataset.

## 3. Data Representation & Preprocessing

The `src/dataset.py` file defines the `ChessDataset` class, which inherits from `torch.utils.data.Dataset`. This class performs the "on-the-fly" transformation of raw FEN strings into numerical tensors.

### Tensor Representation ($18 \times 8 \times 8$)
Each chess position is converted into an $18 \times 8 \times 8$ bitboard tensor to provide the CNN with full spatial and contextual information:
* **Layers 0–11:** Piece locations (P, N, B, R, Q, K for both White and Black).
* **Layer 12:** Side to move (All 1s if White, 0s if Black).
* **Layers 13–16:** Castling rights (White O-O, White O-O-O, Black O-O, Black O-O-O).
* **Layer 17:** En Passant target square (1 on the specific square, 0 elsewhere).

### Label Normalization
To ensure smooth gradient descent, centipawn (CP) evaluations are squashed into a range of $[-1, 1]$ using the hyperbolic tangent function:

$$y = \tanh\left(\frac{cp}{300}\right)$$

In the case of a **Forced Mate**, the evaluation is set directly to a normalized value of **+1.0** (if White is winning) or **-1.0** (if Black is winning), representing a terminal advantage.
